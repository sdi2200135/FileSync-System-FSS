FileSync System (FSS)

Unix file synchronization system σε C, χρησιμοποιώντας inotify, FIFOs, fork/exec και low-level I/O syscalls για real-time mirroring αρχείων.

C (gcc -Wall -g) Linux/Unix IPC · inotify · FIFOs Low-level I/O

📖 Σχετικά με την Εργασία

Η παρούσα εργασία αποτελεί την 1η Προγραμματιστική Εργασία του μαθήματος «Προγραμματισμός Συστημάτων». Υλοποιεί ένα σύστημα real-time συγχρονισμού αρχείων από έναν source φάκελο σε έναν target φάκελο, χρησιμοποιώντας αποκλειστικά low-level system calls.

📡 Real-time Monitoring

Χρήση inotify για ανίχνευση δημιουργίας, τροποποίησης και διαγραφής αρχείων στον source φάκελο.

🔗 IPC Mechanisms

Δύο named pipes (FIFOs) για console↔manager και anonymous pipes για worker→manager.

⚙️ Process Model

fork() + exec() για κάθε sync job — ένας worker process ανά αλλαγή αρχείου.

Σημείωση: Η παρούσα υλοποίηση δεν καλύπτει πλήρως την εκφώνηση της εργασίας. Δείτε τη σελίδα Περιορισμοί για την πλήρη λίστα αποκλίσεων.

🏗️ Components

Το σύστημα αποτελείται από 4 executables. Πατήστε σε κάποιο για λεπτομέρειες.

Console UI

Διεπαφή χρήστη — στέλνει εντολές στον manager μέσω FIFO.

Manager daemon

Κεντρικός daemon — monitors, multiplexes, dispatch commands.

Worker sync

Εκτελεί ένα sync job — αντίγραφο αρχείου ή φακέλου.

fss_script.sh utility

Bash script για reports και cleanup.

⚡ Key Concepts

select() Multiplexing

Ο manager περιμένει ταυτόχρονα σε fss_in FIFO και inotify_fd.

dup2() Redirection

Ο worker γράφει το EXEC_REPORT στο STDOUT_FILENO που έχει ανακατευθυνθεί σε pipe.

Linked Lists

SyncInfo και WatchEntry ως απλές συνδεδεμένες λίστες.

Low-level I/O

open/read/write/unlink/close αντί για stdio — χωρίς system(), cp ή rsync.

Υψηλού επιπέδου σχεδίαση και ροή δεδομένων

📊 High-Level Architecture

+-------------+ fss_in +---------------+ | fss_console | ----------------------> | fss_manager | | | <---------------------- | | +-------------+ fss_out +-------+-------+ | fork() + exec()| (pipe for stdout) v +-----------------+ | worker | | (one per job) | +-----------------+ | v source_dir → target_dir

🔄 Ροή Δεδομένων

  1. Console → fss_in (FIFO)Ο χρήστης πληκτρολογεί εντολή. Η console τη γράφει στο fss_in.
  2. Manager διαβάζει από fss_inΟ manager έχει κάνει open("fss_in", O_RDONLY) και περιμένει με select().
  3. Manager απαντάει μέσω fss_outΓράφει response στο fss_out FIFO που έχει ανοίξει O_WRONLY.
  4. Console διαβάζει από fss_outΧρήση select() με timeout 1s για drain όλων των γραμμών.
  5. Manager παρακολουθεί με inotifyΚάθε source φάκελος έχει inotify_add_watch για CREATE/MODIFY/DELETE.
  6. Spawn workerΣε κάθε event: fork(), dup2(pipefd[1], STDOUT_FILENO), execl("./worker", ...).
  7. Worker εκτελεί syncFULL: recursive copy. ADDED/MODIFIED: single file copy. DELETED: unlink.
  8. Worker γράφει EXEC_REPORTΓράφει στο STDOUT (που είναι redirected στο pipe).
  9. Manager διαβάζει από pipeParse STATUS: και DETAILS:, γράφει στο manager_logfile.txt.

🧠 In-Memory Structures

SyncInfo — Linked List

typedef struct SyncInfo {
    char source[256];           // source path
    char target[256];           // target path
    char status[20];            // "idle", "SUCCESS", ...
    char last_sync_time[20];    // timestamp
    int  active;                 // is it monitored?
    int  error_count;            // total errors
    struct SyncInfo* next;       // next node
} SyncInfo;

WatchEntry — Linked List

typedef struct WatchEntry {
    int  wd;                    // inotify watch descriptor
    char source[256];         // source path
    struct WatchEntry *next;    // next node
} WatchEntry;
Γιατί linked lists: Μικρός αριθμός monitored directories — δεν χρειάζεται hash table. Linear search είναι αρκετά γρήγορη.

🎯 Design Choices

  1. select() για multiplexingΟ manager περιμένει ταυτόχρονα σε FIFO και inotify fd — χωρίς threads.
  2. Worker per job, forked on demandStateless workers, isolation σε failures, απλός κώδικας.
  3. Anonymous pipe per workerΟ worker γράφει στο stdout που έχει γίνει dup2 στο pipe.
  4. Error aggregation in workerΌλα τα σφάλματα μαζεύονται σε error_log[] και εκπέμπονται στο τέλος.
  5. Blocking FIFOsΟ manager ανοίγει O_RDONLY, η console O_WRONLY. Χρειάζεται σωστή σειρά startup.

fss_console

User Interface — fss_console.c

1 Command Line

./fss_console -l <console_logfile>
Σημείωση: Το -l argument ελέγχεται αλλά η τιμή του αγνοείται. Το log file είναι hardcoded ως console_logfile.txt (μέσω #define log_file).

2 Λειτουργία

  1. Έλεγχος argumentsΑν argc != 3 ή argv[1] != "-l" → exit.
  2. Άνοιγμα FIFOsfd_in = open("fss_in", O_WRONLY), fd_out = open("fss_out", O_RDWR).
  3. Ανάγνωση stdinfgets(message, ...), αφαίρεση newline.
  4. Logginglog_entry_file(message) + newline_in_file().
  5. Αποστολή εντολήςwrite(fd_in, message, strlen+1).
  6. Λήψη απάντησηςLoop select() με timeout 1s στο fd_out.
  7. ΈξοδοςΑν η εντολή ήταν shutdown → break.

3 Response Draining

Χρήση select() με timeout για να διαβαστούν ΟΛΕΣ οι γραμμές της απάντησης:

do {
    FD_ZERO(&read_fds);
    FD_SET(fd_out, &read_fds);
    timeout.tv_sec = 1;
    
    retval = select(fd_out + 1, &read_fds, NULL, NULL, &timeout);
    
    if (retval > 0) {
        ssize_t bytes_read = read(fd_out, response, sizeof(response) - 1);
        if (bytes_read > 0) {
            response[bytes_read] = '\0';
            log_entry(response);
            log_entry_file(response);
        }
    }
} while (retval != 0);  // timeout = no more data
Γιατί timeout=1s: Ο manager μπορεί να στείλει πολλαπλές γραμμές (π.χ. για add: "Added directory" + "Monitoring started"). Το loop σταματάει όταν περάσει 1 δευτερόλεπτο χωρίς νέα δεδομένα.

4 Logging Format

fss_manager

Central Daemon — fss_manager.c

1 Command Line

./fss_manager -c <config_file> [-n <worker_limit>]
Απόκλιση από spec:
  • Το -l flag δεν γίνεται parse — το log file είναι hardcoded ως manager_logfile.txt.
  • Το -n διαβάζεται αλλά πάντα αντικαθίσταται από WORKER_LIMIT = 5.

2 Startup Sequence

  1. Parse argumentsΑνάγνωση -c (required) και -n (optional, αγνοείται).
  2. Κλήση sigchld_handler(SIGCHLD)⚠️ Ο handler δεν εγκαθίσταται με signal() — απλή κλήση, δεν εκτελείται ποτέ.
  3. Δημιουργία FIFOsmkfifo("fss_in", 0600) και mkfifo("fss_out", 0600). Δεν γίνεται unlink() πρώτα.
  4. Άνοιγμα FIFOsfd_in = open(O_RDONLY), fd_out = open(O_WRONLY).
  5. Άνοιγμα config fileParse κάθε γραμμής με sscanf("(%[^,],%[^)])", source, target).
  6. Για κάθε pairLaunch FULL worker, add_sync_info, inotify_add_watch, add_watch_entry.
  7. Main loopselect() σε fd_in και inotify_fd.
Σημείωση: Δεν εκτυπώνονται μηνύματα "Added directory" / "Monitoring started" για τα config-file pairs (αντίθετα με το spec).

3 Main Loop

while (1) {
    fd_set readfds;
    FD_ZERO(&readfds);
    FD_SET(fd_in, &readfds);
    FD_SET(inotify_fd, &readfds);
    
    max_fd = (fd_in > inotify_fd) ? fd_in : inotify_fd;
    
    select(max_fd + 1, &readfds, NULL, NULL, NULL);
    
    if (FD_ISSET(fd_in, &readfds)) {
        read(fd_in, buffer, ...);
        // dispatch: shutdown / add / cancel / status / sync
    }
    
    if (FD_ISSET(inotify_fd, &readfds)) {
        len = read(inotify_fd, buf, ...);
        // walk events, spawn worker for each
    }
}

5 inotify Event Handling

  1. Walk bufferi += sizeof(inotify_event) + event->len για κάθε event.
  2. Determine operationIN_CREATE → "ADDED", IN_MODIFY → "MODIFIED", IN_DELETE → "DELETED".
  3. Lookup sourcelookup_source_from_wd(event->wd) από το WatchEntry list.
  4. Get targetget_target_for_source(source_dir) από το SyncInfo list.
  5. Spawn workerworker_on(source_dir, target, event->name, operation).

worker

File Sync Executor — worker.c

1 Invocation

./worker <source> <target> <filename> <operation>

Όπου operation ∈ { FULL, ADDED, MODIFIED, DELETED }.

2 Operations

FULL + filename "ALL"

copy_directory(source, target):
    dir = opendir(source)
    mkdir(target, 0755)
    
    while (entry = readdir(dir)):
        if entry is "." or "..": continue
        
        path_src = source/entry
        path_dst = target/entry
        stat(path_src, &st)
        
        if S_ISDIR: copy_directory(path_src, path_dst)   // recursive
        if S_ISREG: copy_file(path_src, path_dst)

ADDED / MODIFIED

copy_file(source/filename, target/filename)

DELETED

unlink(target/filename)

3 copy_file — Low-level I/O

int fd_in = open(src, O_RDONLY);
int fd_out = open(dst, O_CREAT | O_WRONLY | O_TRUNC, 0644);

while ((bytes_read = read(fd_in, buffer, BUFFER_SIZE)) > 0) {
    bytes_written = write(fd_out, buffer, bytes_read);
    if (bytes_written != bytes_read) {
        log_error("Write error");
        skipped_files++;
        break;
    }
}

close(fd_in);
close(fd_out);
Χωρίς system()/cp/rsync: Όλα τα I/O γίνονται με low-level syscalls (open/read/write/unlink/close/stat/mkdir/opendir/readdir).

4 Error Handling

Όλα τα σφάλματα μαζεύονται σε error_log[2048]:

void log_error(char *msg) {
    strcat(error_log, "- ");
    strcat(error_log, msg);
    strcat(error_log, "\n");
}

Κλήση με strerror(errno) μετά από κάθε αποτυχημένο syscall.

5 EXEC_REPORT

Ο worker γράφει στο STDOUT_FILENO (που έχει γίνει dup2 στο pipe):

EXEC_REPORT_START STATUS: SUCCESS | PARTIAL | ERROR DETAILS: <n> files copied, <m> skipped ERRORS: - <reason1> - <reason2> EXEC_REPORT_END

Status Logic

  • SUCCESS: error_log κενό
  • PARTIAL: υπάρχουν errors αλλά copied_files > 0
  • ERROR: errors χωρίς κανένα επιτυχές copy

Παράδειγμα

EXEC_REPORT_START STATUS: SUCCESS DETAILS: 10 files copied, 0 skipped EXEC_REPORT_END

6 Return Value

Επιστρέφει 0 σε κάθε περίπτωση (ακόμα και σε σφάλματα). Ο manager δεν ελέγχει το exit code — βασίζεται αποκλειστικά στο EXEC_REPORT text.

fss_script.sh

Report Generation & Cleanup Utility

1 Usage

./fss_script.sh -p <path> -c <command>

Ο parser διαβάζει τα arguments σε loop και ελέγχει μόνο -p και -c.

2 Commands

CommandBehavior
listAll Parse log file line by line, strip [ ], print source -> target [Last Sync: date time] [status].
listMonitored Ίδιο parsing, μόνο γραμμές με status SUCCESS ή PARTIAL.
listStopped Ίδιο parsing, μόνο γραμμές με status ERROR.
purge Αν -p is file → rm. Αν directory → ελέγχει αν είναι source (αρνείται) ή target (rm -rf).

3 Parsing Logic

while IFS= read -r line || [ -n "$line" ]; do
    [[ -z "$line" ]] && continue              # skip blank lines
    
    read -ra raw_fields <<< "$line"
    [[ "${raw_fields[2]}" != \[* ]] && continue   # skip non-full-format
    
    clean_line=${line//[\[\]]/}                  # remove brackets
    read -ra fields <<< "$clean_line"
    
    date="${fields[0]}"
    time="${fields[1]}"
    source="${fields[2]}"
    target="${fields[3]}"
    status="${fields[6]}"
done < "$path"

4 Purge Logic

  1. Αν -p is regular filerm "$path" + "Purge complete."
  2. Αν -p is directoryΔιαβάζει manager_logfile.txt (hardcoded), ψάχνει αν το path είναι source ή target.
  3. Αν είναι sourceΑρνείται — "The $path is a source directory."
  4. Αν είναι targetrm -rf "$path" + "Purge complete."
Hardcoded path: Για directory case, το script διαβάζει manager_logfile.txt unconditionally — δεν παράγεται από το -p. Αυτό γιατί το target directory θα είχε ήδη διαγραφεί όταν θα έκανε lookup.

5 Παραδείγματα

# Μόνο αποτυχημένα

🐛 Αποκλίσεις από το Spec

1
-l manager log argument ignored Το -l flag δεν γίνεται parse — το log path είναι hardcoded ως manager_logfile.txt στο log_worker_utils.c.
2
-l console log argument ignored (value) Το -l argument ελέγχεται ότι υπάρχει αλλά η τιμή αγνοείται. Το log file είναι hardcoded ως console_logfile.txt.
3
SIGCHLD handler not installed Ο κώδικας καλεί sigchld_handler(SIGCHLD) χωρίς signal()/sigaction(). Ο handler δεν εκτελείται ποτέ → zombie workers συσσωρεύονται.
4
No worker_limit queue Το -n διαβάζεται αλλά πάντα αντικαθίσταται από WORKER_LIMIT = 5. Δεν υπάρχει queue — κάθε event spawns worker άμεσα.
5
Config file format mismatch Ο manager περιμένει (source,target) per line (παρενθέσεις + κόμμα). Το spec ζητάει space-separated format.
6
FIFOs not cleaned up before mkfifo Αν τα fss_in/fss_out υπάρχουν από προηγούμενη εκτέλεση, το mkfifo αποτυγχάνει → ο manager δεν ξεκινά.
7
No "Added directory" / "Monitoring started" for config entries Το spec απαιτεί αυτά τα μηνύματα on startup για κάθε config-file pair. Ο κώδικας τα εκτυπώνει μόνο για runtime add.
8
No duplicate-add check Το add πάντα ξεκινάει νέο full sync ακόμα και αν το source είναι ήδη registered. Το spec θέλει Already in queue: <src>.
9
No "Directory not monitored" for cancel Το cancel πάντα τυπώνει "Monitoring stopped" ανεξάρτητα από το αν το source ήταν monitored.
10
No "Sync already in progress" handling Το sync πάντα κάνει fork νέου worker. Δεν ελέγχει αν υπάρχει ήδη sync για το source.
11
status_mode / sync_mode no NULL check Αν find_sync_info επιστρέψει NULL, γίνεται dereference σε new->source → segfault. Το spec θέλει Directory not monitored: <src>.
12
No graceful shutdown Το shutdown_mode τυπώνει 4 μηνύματα και επιστρέφει. Το main loop κάνει break χωρίς αναμονή ενεργών workers.
13
Inconsistent manager log format Τα worker results χρησιμοποιούν full format, αλλά όλα τα άλλα μηνύματα χρησιμοποιούν [TS] <message>. Δύο formats στο ίδιο log.
14
Makefile not true separate compilation Το MANAGER_OBJS ορίζεται αλλά δεν χρησιμοποιείται. Όλα τα sources compile σε ένα gcc call.
15
fss_script.sh purge reads hardcoded path Για directory case, το script διαβάζει manager_logfile.txt unconditionally αντί να παράγει από το -p.

🧪 Testing Checklist — Αποτελέσματα

✓ Start manager με 2-line (src,tgt) config → 2 FULL workers, 2 inotify watches
✗ Start με space-separated config → no watches (sscanf fails silently)
✗ Start manager twice without make clean → mkfifo fails, open fails, manager exits
✓ add /src /dst → "Added directory" + "Monitoring started" + new worker
⚠️ add already known source → syncs again (no "Already in queue")
✓ Create file in monitored source → ADDED entry, file copied
✓ Modify file → MODIFIED entry, target overwritten
✓ Delete file → DELETED entry, target file removed
⚠️ cancel /src → "Monitoring stopped" even if never monitored
✓ status /src (known) → Directory/Target/Last Sync/Errors/Status
✗ status /src (unknown) → SEGFAULT
✗ sync /src (unknown) → SEGFAULT
⚠️ shutdown → 4 messages, exits without waiting for workers
✓ ./fss_script.sh -p manager_logfile.txt -c listAll → one line per directory
✓ ./fss_script.sh -p /backup/pics -c purge → target directory removed

🎯 Τι Λειτουργεί Σωστά

✅ Real-time Sync

Το inotify monitoring και το άμεσο sync αρχείων λειτουργούν σωστά για flat directories.

✅ IPC Mechanisms

FIFOs, anonymous pipes, dup2 redirection — όλα λειτουργούν όπως προβλέπεται.

✅ Low-level I/O

Ο worker χρησιμοποιεί syscalls (open/read/write/unlink) χωρίς system() ή shell commands.

✅ Error Aggregation

Τα σφάλματα συσσωρεύονται και αναφέρονται στο EXEC_REPORT στο τέλος κάθε job.

🔧 Προτεινόμενες Βελτιώσεις

  1. Εγκατάσταση SIGCHLD handlerΧρήση sigaction(SIGCHLD, &sa, NULL) για reaping των zombie workers.
  2. NULL checks στα status/syncΈλεγχος αν find_sync_info επιστρέφει NULL πριν το dereference.
  3. Parse -l argumentsΧρήση των paths από τα CLI arguments αντί για hardcoded log files.
  4. Duplicate detection στο addΈλεγχος αν το source υπάρχει ήδη — μήνυμα "Already in queue".
  5. Graceful shutdownΑναμονή για active workers με waitpid() πριν το exit.
  6. FIFO cleanupunlink() πριν το mkfifo() για να αποφευχθεί το startup failure.
  7. Uniform log formatΊδιο format για όλα τα entries του manager log file.
  8. Worker limit queueΧρήση του -n value με bounded queue για αποφυγή υπερφόρτωσης.

📌 Συμπέρασμα

Το σύστημα υλοποιεί επιτυχώς τις βασικές λειτουργίες real-time file synchronization με inotify, FIFOs και fork/exec. Ωστόσο, υπάρχουν 15 σημαντικές αποκλίσεις από την εκφώνηση που αφορούν κυρίως:

  • Robustness — NULL checks, graceful shutdown, SIGCHLD
  • Configuration — CLI arguments ignored, format mismatch
  • Consistency — mixed log formats, no duplicate detection
  • Scalability — no worker queue, no worker limit enforcement

Οι αποκλίσεις είναι καταγεγραμμένες ρητά στο README της εργασίας, δείχνοντας πλήρη επίγνωση των περιορισμών της υλοποίησης.
